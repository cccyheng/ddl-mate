# 原生端时间助手：把「明天晚上8点 / 下周五18:00 / 下节课前」变成明确截止时间

> 授权范围：`.supervision/native-time-assistant-assignment.md`（只做这一件有界任务）

这是 **iOS 原生端（Expo / React Native）的本地时间助手**：在「新建 / 编辑任务」的截止时间旁边，
给一个可折叠的小卡片，把简短时间短语换算成明确时间。**纯本地规则，不联网、不调用大模型、不加依赖、不写数据库。**

Web 端的能力与接口契约见 [`v1.2-time-assistant.md`](v1.2-time-assistant.md)；原生端只保留其中**核心且可离线**的部分，
不照搬后端全部宽度，具体范围见下面的「明确不支持」。

---

## 1. 怎么用（一句话）

1. 展开截止时间卡片里的「时间助手」；
2. 输入短语（例如 `明天晚上8点`），确认「通知参考时间」（默认就是现在，可改成通知发布的时间）；
3. 点「解析这个短语」——助手只展示结果，**不会改动任何东西**；
4. 只有点「**采用此时间**」才会把结果填进上面的截止时间输入框；
5. 填进去之后仍然可以手工修改；**不点页面下方的保存，就不会保存。**

课程类说法（`下节课前`）用的是表单里「所属课程」**明确选择**的那门课与它在本机的真实课表。

---

## 2. 明确支持的写法

日历语义固定：业务时区 **北京时间（Asia/Shanghai）**，**一周从周一开始**；「今天 / 本周」都以「通知参考时间」所在的北京自然日为准。

### 2.1 精确日期 + 时刻

| 写法 | 结果 |
| --- | --- |
| `2026-10-20 23:00` / `2026-10-20T23:00` / `2026/10/20 8:05` | 该日期的该时刻 |
| `2026年12月31日 23:30` / `2026-01-31 23:59` | 中文年月日同样支持 |
| 跨月 / 跨年 / 闰日 | `2027-01-01 00:00`、`2028-02-29 12:00` 都可 |

### 2.2 相对日 + 时刻

| 写法 | 结果 |
| --- | --- |
| `今天 22:00` / `明天 18:00` / `后天 08:30` / `大后天 07:00` | 参考日 +0 / +1 / +2 / +3 天 |
| `明天晚上8点` / `明晚8点` / `今晚8点` | 20:00（半日前缀做无歧义的 12 小时换算） |
| `明天下午3点` / `明天晚上8点半` / `明天中午1点` | 15:00 / 20:30 / 13:00 |
| `明天凌晨1点` / `明天上午9点` / `明天早上7点` | 01:00 / 09:00 / 07:00 |
| `明天22点` / `明天22点30分` / `明天8点半` / `明天3点一刻` | 中文时刻写法都支持 |

**缺少时刻时绝不补默认值**：`明天`、`下周五`、`今晚`、`22:00`、`下午3点` 都会要求你补全，
**不会**默认成 23:59，也**不会**默认成 18:00。

### 2.3 星期与周

| 写法 | 结果 |
| --- | --- |
| `本周五 18:00` / `这周六 09:00` | 本周对应的那一天（**即使已经过去也如实解析**，结果会标注「已经过去」） |
| `下周一 08:00` / `下星期五 20:00` / `下个星期三 10:00` | 下一个自然周对应的一天 |
| `本星期天` / `这个星期二` | 同上 |
| 不带周前缀的 `周五 18:00` | 按**本周**理解；这一天本周已经过去时**不自动跳周**，会要求你写 `下周五` 或具体日期 |

### 2.4 课程边界（必须先在表单里选好课程）

精确支持的短语只有：

```
下节课前 / 下节课之前 / 下一节课前
下次课前 / 下次课之前 / 下次上课前 / 下次上课之前
本周这门课前 / 这周这门课前 / 下周这门课前 / 下个星期这门课前
本周X上课前 / 这周X上课前 / 下周X上课前
```

规则：

- **课程必须由你在表单里明确选择**：文字里出现另一门已有课程的名称时，助手会要求澄清，不会忽略它按当前课程算；
- 复用全站唯一教学周判定 `occursOn`：遵守**学期第一周周一、起止教学周、单双周**；没有教学周信息的旧课表按**每周**处理；
- **参考时间之后才开始的课**才算「下一次」：正在上的那节不算，**开始时间正好等于参考时间也不算**；
- 窗口语义：
  - `下节课前 / 下次课前` → 从参考时间起**最多向后 366 天**找最近一节；
  - `下周…` → **严格下一个自然周**；这一周没有课就说没有，**绝不越周**；
  - `本周…` → 参考当天起到本周日为止；`本周五上课前 / 下周五上课前` 只考虑那一天；
- 窗口内有多节时**取最早的一节**，并说明「该窗口内还有 N 节更晚的课」；同一时刻的重复课表会去重；
- **候选截止 = 上课开始边界**：说明里明确写「按开课时间作为截止边界，助手不会提前扣分钟」，不会自作主张减掉几分钟。

## 3. 必须保守拒绝 / 要求补全的写法

助手宁可要求你补全，也不猜。

| 输入 | 结果 |
| --- | --- |
| `明天`、`下周五`、`今晚`、`22:00` | 需要补全（只有日期或只有时刻） |
| `尽快`、`随时`、`以后`、`周末`、`月底`、`下周` | 需要补全（不是一个确定时间点） |
| `每周五 18:00`、`每天 08:00` | 需要补全（重复发生，不是一次性截止） |
| `明天 10:00，后天 12:00`、`明天 10:00 或 14:00` | 需要补全（多个日期 / 多个时刻，**不取第一个**） |
| `本周一到周五`、`2026-10-01 到 2026-10-07` | 需要补全（范围） |
| `10月20日 22:00`、`20号 10:00` | 需要补全（只有月日 / 几号，没有年份） |
| `明天 25:00`、`明天 22:75`、`2026-02-30 10:00`、`2027-02-29 10:00` | 需要补全（日期 / 时刻不存在，严格校验，不会被静默滚动） |
| `明天下午15点`、`明天上午23点`、`明天凌晨12点`、`晚上12点`、`明天下午0点` | 需要补全（半日与时刻矛盾 / 中午还是午夜不明确） |
| `下下周五18:00` | 需要补全（不支持「下下」这类周偏移，**不会被截成「下」**） |
| `明天18:000`、`明天123:00` | 需要补全（多余数字不会被截断后静默采用） |
| `明天18:00之后`、`明天18点开始`、`明天18:00左右` | 需要补全（未定义的修饰词） |
| `下节课前两小时`、`下节课前或下周五上课前` | 需要补全（不做「提前两小时」换算；多个「课前」不取第一个） |
| `下次数学课前`、`下周实验课前`、`上课前`、`课前` | 需要补全（带课程名 / 类型限定，不猜是哪一节） |
| `取消明天的作业`、`延期到下周五`、`改到下周 22:00` | 暂不支持（否定 / 延期 / 更改） |
| `三天以前`、`两周之前` | 暂不支持（相对过去的说法） |
| `国庆后第一节课前`、`寒假前`、`考试周` | 暂不支持（需要校历，本机没有校历数据） |

**允许的包装词**（不改变语义）：空白与标点、`前` / `之前` / `截止` / `截至`、
`提交` / `提交到` / `上交` / `上传` / `发送` / `完成`、`请` / `请在` / `请于` / `于` / `在` / `的` / `要` / `需` / `需要` / `务必`。
所以 `明天18:00前交`、`明天 22:00 截止`、`请在明天18:00之前提交` 都能通过；
`明天18:00之后` 会被拒绝。这条「**整句覆盖**」策略不依赖否定词黑名单，多余字符一律拒绝。

**长度校验**：空短语、或超过 **500 字**，会直接给可见提示，不进解析。

## 4. 时区契约（固定北京时间）

- 助手**固定**按 `Asia/Shanghai` 计算，**不跟随手机系统时区**：手机在 UTC 还是纽约，
  `明天晚上8点` 都解释为北京时间次日 20:00；
- 「通知参考时间」输入框是**北京时间墙上时间**，并标注「相对时间按这个时间计算」；带偏移的参考时间
  （例如 `2026-10-13T04:00:00Z`）会先换算到北京自然日再算「今天 / 明天」；
- 结果里的时间一律带 `+08:00`，展示为 `2026-10-15 08:00 周四` 这样的可读形式；
- 支持的日历范围 **1900–2199**：超出范围的日期、以及相对推演越界（例如参考日是 2199-12-31 时说「明天」）
  都会如实要求改写，不会编一个时间出来。

## 5. 交互契约（防「过期建议」）

| 情况 | 行为 |
| --- | --- |
| 点「解析」 | **只展示**结果，不改草稿、不写数据库 |
| 点「采用此时间」 | 先用纯函数把这次采用结算清楚（含用**最新**输入重新解析、核对展示的候选仍是同一个时间点），确认有效才把结果填进**截止时间**一个字段，按钮随即变为「已采用这条时间」。结算发生在按钮的事件处理器里，界面状态更新函数里**没有任何副作用**，因此父组件的写入回调只会被调用一次、也不会在渲染期触发 |
| 短语 / 参考时间 / 课程 / 课表快照 / 课程快照变化 | 已展示的建议**立即作废**，显示「请重新解析」，采用按钮禁用 |
| 课表被改动（同一门课改了时间 / 加了课） | 同上（比较的是课表**内容**，不是数组引用；内容相同的新数组不会误判过期） |
| 选中的课程被删除 / 改名 / 换编号 | 同上；采用时还会再检查这门课是否存在，不存在就不写 |
| 手工修改截止时间 | 建议作废；**手工值永远保留**，不会被旧建议覆盖 |
| 把「通知参考时间」清空 | **如实报错**并停在那里，**不会**偷偷填回「现在」（那会把相对时间算到另一天）；想恢复点「重新设为现在」 |
| 建议的时间按**真实当前时刻**已经过去 | 照实提示「按现在的北京时间看，这个时间已经过去了；助手不会替你改成别的时间」——候选时间**不会变**。参考时间只用于推算相对日期，不会被冒充成「现在」 |
| 采用时 | 用**最新**输入再校验一次；过期 / 无候选 / 选中的课不存在，一律不写入 |
| 保存中 / 数据未就绪 | 助手整体禁用或不显示；**不弹任何权限提示** |
| 换任务、关闭面板 | 建议状态清空，不会把上一条任务的结果带过来 |

手工输入始终保留：助手只改截止时间一个字段，采用后仍可继续手改。
助手**不改动**说明、原文、课程等任何其它字段，也不影响原有的「原文只读 / 追加原文」流程。

## 7. 明确不支持 / 已知限制（不夸大）

- **不是大模型**：不做整段通知的语义抽取；复杂句（否定 / 延期 / 更改 / 范围 / 相对过去）一律保守拒绝；
- 需要校历的说法（国庆、寒假、考试周、「第几教学周」）不支持；
- `下下周五` 这类多周偏移不支持；不带周前缀的「周X」按本周理解且已过去不跳周；
- 课表匹配只按**课程 + 星期 + 教学周规则**，不区分同一门课的「理论 / 实验」课堂类型，
  所以 `下次实验课前` 被拒绝而不是猜一节；
- 通知导入的候选列表（Web 端有）在原生端**没有**接入助手：原生端只接了任务表单；
- 助手是**辅助输入**：最终是否采用由你决定，所有结果都不写库；
- 原生端测试跑在 Node 侧（`node:sqlite` 内存库），验证的是 SQL / 事务 / 纯逻辑，
  **验证不了**原生绑定、真机 UI 与真机文件持久化；本轮**未做**手机 / 真机验证。

# 今日学习计划（原生）

「今日学习计划」回答一个问题：**今天我给自己划出的这段时间里，按我选的任务和每任务的计划分钟数，
排不排得下；排得下的话具体几点做什么，排不下的还差多少、为什么。**

它是一条**规则明确的本地计算**（不是 AI、不联网、不调用任何外部服务），
只有用户明确点「采用并保存」时才写入本机。

## 从哪里进

- 「今天」标签页 →「安排今天的学习计划」；
- 「任务」标签页 →「今日学习计划」。

两条标签页都有**自己的原生栈**，所以从任意一条进去，返回手势与返回按钮都正常，
并且「今天 → 任务详情 / 编辑」仍然在同一个栈里。路由名是 `TodayPlan`。

## 使用流程

1. **填今天的学习时段**：最多 4 段，`HH:mm` 格式，同一天内；空白行 = 没有这一段。
   相邻可以（`08:00-09:00` 接 `09:00-10:00`），**重叠会当场报错**，不支持跨天。
2. **勾选今天要做的任务**：只列出「待办 / 进行中」的任务；每个被勾中的任务都要填
   **本次安排分钟数**（1–1440 的整数）。
   - 任务如果明确填过 1–1440 分钟的预计用时，会作为**可编辑的便利初值**预填，并写明来源；
   - 没填过 / 填 0 / 超过 1440 的，一律**留空**，需要你自己填；
   - 进行中（DOING）的任务会预填它原来的预计用时并提示「进度没有被测量，请确认」；
   - 这里填的分钟数**永远不会**去改任务的「预计用时」，也不会改状态和 DDL。
3. **生成预览**：只读、零写库。会显示
   - 按时间顺序的块：任务标题 + `起-止` + 分钟数；
   - 每个选中任务的 `计划 / 已排 / 未排` 分钟数与**排不下的具体原因**；
   - 今天可用的时段、其中真正的空闲缺口、以及上课占用（整节课都算忙，课间也算）。
4. **采用并保存**：写入本机数据库。今天已经有一份计划时会先弹出确认框；
   保存**只**写这一份计划，不动任何任务、课程、课表。

预览是**会被作废的**：改了时段 / 换了任务 / 改了分钟数，或者相关任务与课表在别处变了，
预览立刻标明「已经过期」，必须先重新生成才能保存。**不会保存一份用户没确认过的计划。**

## 排布规则（就是代码在做的事）

1. 学习时段先校验、再去掉已经过去的部分（「现在」**向上取整到下一分钟**）。
2. 今天真实有课的课表（按教学周 / 单双周判定，学期范围外与别的星期几都不算）
   按**整节课区间**算占用。
3. 忙区间先合并重叠与相邻，再从时段里减掉，剩下的就是**空闲缺口**。
4. 任务按「最早 DDL → 优先级高 → id 小」排序；**没有 DDL 的排在最后**。
5. 每个任务在自己 DDL 之前（DDL 那一分钟不含）的空闲缺口里顺序填充，
   允许跨时段 / 跨课拆分；每块至少 1 分钟、必须是正整数分钟。
6. 一个任务排满后，后面的任务继续用剩下的缺口（不丢容量）。
7. 每个任务恒有：**已排 + 未排 = 计划分钟数**。

## 保存下来的东西

存在既有的 `app_settings` 键值表里，键是 `daily_plan.today`，值是带版本号的紧凑 JSON：
日期、时段、选中任务与分钟数、块、每任务结果、以及一份**内容指纹**（用于「相关任务变了」的提示）。
**没有新表、没有 schema 版本变更、没有新依赖。**

- 保存时会在**同一个事务里**重新读一遍任务 / 课表 / 课程，用**同一时间锚点**重算一遍，
  与用户确认过的那份预览比对（块身份 + 每任务结果 + 内容指纹）。任何一处对不上 → 拒绝保存。
- 如果提交那一刻计划块**已经开始**（时间溜走了），也拒绝保存并请你重新生成 ——
  绝不悄悄改排一版你没确认过的计划。
- 两个页面同时打开时用**版本号**做乐观锁：后到的那个会被拒绝，不会互相静默覆盖。
- 读回时对存储内容做**严格结构校验**：字段缺失、类型不对、取不到的值一律不猜，
  整条记录判为「读不出来」，并**原样保留**那条记录，绝不删除或改写。

## 已保存计划与「情况变了」

已保存的那一份与正在编辑的预览**分开显示**。任务被改名、改 DDL、标记完成或被删除时，
计划里的块**保持原样**并逐条提示差异（不会自动重排、不会自动把任务标成完成）；
需要新的一版时由你显式重新生成。

**任务完成永远靠你自己在任务页勾选。**

### 保存后的读回（「已保存」与「读回来了」是两件事）

- 保存成功后界面会立刻读回一次。读到了：内容与版本号一起更新为刚保存的那一份。
- **读回失败**：保留「已经保存」这件事与版本号，但**不显示任何内容**——
  上一版计划绝不会顶着新版本号显示成「今天的计划」；页面会明说「已保存，但没读回来」，
  并给一个「重新读一次」。
- 只要本机**已知有今天的计划记录**（哪怕内容一时读不回来），再次点「采用并保存」**仍然要确认**，
  不会因为一次读回失败就把替换确认这道关绕过去。
- 读回的版本号是**单调**的：保存之前发出、保存之后才回来的旧读回会被整条丢弃，
  绝不出现「旧内容配新版本号」；保存开始时会把读回闸门往前推一格，在途的旧读回一律作废。

## 跨零点

草稿与预览都带日期。跨过上海零点后：旧预览立即作废，页面上出现「已经跨过零点」，
只有在你点「以今天重新开始」并确认之后才清空草稿 —— **绝不把昨天的计划当成今天的**，
也不会替你悄悄丢掉还没保存的输入。

## 限制（明确写出来，不夸大）

- 只在本地算，**不联网、不接 AI、不发通知、不自动重排**；关掉 App 不会有任何后台动作。
- 排序是「按截止时间优先的贪心」，**不是全局最优**，也不代表任务能提前完成；
  它不测量任务进度，`计划分钟数` **不等于剩余工作量**。
- 计划块只表示「这段时间打算做这个」，**不会**修改任务的 DDL、状态、预计用时或来源。
- 保存失败 / 被拒绝时一个字节都不会写入；「已保存但没读回来」会如实说明，并隐藏旧内容。
- 计划的读写走应用**已有的公共串行写队列**：与任务、课程、通知导入的写入严格串行。

# 原生端「通知转待办」：把群通知原文变成逐条核对的待办

> 工作区：`C:\Users\33284\OneDrive\文档\ChatGPT\大学生ddl`
> 实现：DeepSeek · 独立复核：Codex · 状态：**已实现并自测通过，等待复核**
> 授权范围：`.supervision/native-notice-import-assignment.md`（只做这一件有界任务）
> 交接记录：`.supervision/native-notice-import-handoff.md`

这是 **iOS 原生端（Expo / React Native）本地功能**：把一段**群通知原文**（聊天里复制的文字，
包括群名、发送时间这些消息头）粘贴进来 → 本机按**固定规则**提取候选 → 逐条核对、勾选 →
**明确点保存**之后，整批写进这台手机的 SQLite。

**不是 AI 语义理解，也不是截图 OCR**：没有联网、没有大模型、没有新依赖、没有后端请求。
界面上的说法是「本地规则提取」，不假装它是 AI。

## 1. 怎么用（完整流程）

入口在**任务页**：任务列表上方的「**通知转待办**」按钮（任务栈内新页面「通知转待办」）。

1. **粘贴原文**（上限 **10000 字**）。超出上限会当场报错并给出当前字数与上限，
   **绝不静默截断**。
2. 点「**提取任务**」。这一步**只读**：不写数据库、不改任何任务。
   - 提取到 0 条 → 显示「没有提取到可用的任务」并给出返回入口；
   - 超过单次上限（30 条）→ 顶部用醒目提示说明**一共多少条**、「只列出前 30 条，
     后面的没有被列出来，也不会被保存，请分两次导入」。条数是**过滤掉群名/消息头之后**
     的真实任务数（不会因为原文里有非任务段而少算）。
3. **逐条核对**。每条候选：
   - 「全选 / 全不选 / 单选」勾选，只有勾选的行会被保存；
   - 折叠时只显示：行号、标题、课程、类型、截止时间摘要；
   - **一次只展开一条**（点标题行展开/收起）。展开后可以改：标题、所属课程（含「不关联课程」）、
     类型、截止时间、提交要求、提交方式；
   - 「原文片段」是**只读**的（可长按选中复制），始终能看到；
   - 解析器的保守提示（缺年份、相对说法、多组时间、没有完全一致的课程…）以原话显示在字段下方。
4. 点「**保存勾选的 N 条为待办**」。保存期间按钮禁用（防连点）；校验不过时**就地**显示
   「第 N 行：…」的错误，已改好的内容原样保留。
5. 保存完成后显示结果：新建几条、跳过几条完全重复、每条任务与「查看这条任务」入口、
   「返回任务列表」。**提交之后再点保存不会重复写入**。

### 未保存时的保护

- **原文改过之后必须先重新提取**：候选是按「提取那一刻的原文」算出来的。改动原文之后，
  保存按钮会变灰，页面提示「原文已更改，请重新提取后保存。」；就算绕过界面，保存流程本身
  也会再拦一次。入库的原文一律是**提取快照**，不会出现「旧候选 + 新原文」的错配。
- **覆盖已改好的核对内容之前一定先确认**：点「重新提取」时若有未保存的核对内容，
  会先弹确认框说明「改动会丢失」；**取消不会丢掉任何已改内容**，确认后才按新原文刷新；
- 有未保存草稿时按返回 / 侧滑返回 → 先弹确认框，确认丢弃之后**原样派发被拦下来的那个导航动作**
  （用 `@react-navigation/native` 的 `usePreventRemove`，不是自己挂 `beforeRemove`；
  后者会丢掉原始动作、只能退化成 `goBack`）。**「草稿」不只看原文输入框**：
  - 只粘贴了原文还没提取 → 提示；
  - 提取出 0 条候选 → 提示；
  - 已经把原文清空、但**核对行还在（或已经改过）** → 依然提示，不会因为输入框空了就把改好的候选丢掉；
- **保存进行中不允许离开**：返回会被拦下并给出「正在保存，请稍等」的提示框，
  且**不提供「丢弃」按钮**（避免把「保存中」误判成「没保存」而重复导入）。

## 2. 实际用得到的写法（来自解析器真实语义）

固定的业务时区是**北京时间（Asia/Shanghai）**。解析规则**保守**：拿不准就留空 + 给提示。

| 原文写法 | 结果 |
| --- | --- |
| `2026年10月20日 22:00 前提交到学习通` | 截止 `2026-10-20 22:00`，提交方式「学习通」 |
| `2026-11-03 14:30 前交纸质稿` | 截止 `2026-11-03 14:30`，提交方式「纸质」 |
| `2026年10月15日晚上8点前交` / `下午3点前交` | `20:00` / `15:00`（半日前缀换算） |
| `1. … 2. … 3. …`（编号条目） | 每条各自成候选，**互不串联**（第二条不会借用第一条的时间） |
| `作业一：…；作业二：…`（同一行两条） | 拆成两条候选 |
| `2026年10月8日 08:30 王老师：请下周一交作业` | 第一组日期时间是**聊天发送时间**，不是截止时间 → 留空 |
| `10月15日交作业`（只有月日） | 留空 + 「只有月日没有年份」提示 |
| `2026年10月15日交作业`（只有日期） | 留空 + 「只有日期没有具体时刻」提示 |
| `明天下午交报告` / `下周五前交` / `下节课前交` | 留空 + 「相对说法需要先确定通知是哪一天」提示 |
| `2026年2月30日 23:59 截止` / `2026-10-15 25:00 截止` | 留空 + 「日期或时刻不存在」提示 |
| `提交截止 …，补交截止 …`（两组都像截止） | 留空 + 「有多组日期时间，无法确定哪个是截止时间」提示 |
| `课程通知：2026年10月15日09:00开始讲座` | 留空 + 「看不出它是截止时间」提示（活动开始时间不算 DDL） |
| `a+b@example.edu.cn` / `https://example.edu/path?x=1` | 邮箱与 URL **原样保留**，不会被标点切碎 |
| `数据结构作业三：…`（课程名完全一致） | 自动关联这门课（只做**完全一致**匹配，不做模糊归并） |
| `数据结构作业：请于2026年10月18日22:00前提交报告。`<br>`英语作业：请于2026年10月19日18:00前提交作文。` | **两条独立候选**（各自课程与各自截止时间）—— 这是原生适配层补的边界，见 3.1 |
| `数据结构实验：…`（解析器给出 `LAB`） | 类型显式映射为「项目」，并在任务说明里注明「原类型 LAB」 |
| 群名 `数据结构课程群` | **不会**用来替任务猜课程（群名不是任务里的线索） |

`deadline`、`type`、`submitRequirement`、`submitMethod`、`courseId` 都只是**候选**：
最终写库用的一定是你在核对页上看到并点过保存的那一份。

### 明确不支持（不要期待）

- **不解析相对时间为具体日期**。`明天 / 下周五 / 下节课前` 一律留空并提示；
  想换算可以到「任务表单」用已有的**时间助手**（可编辑参考时间 + 显式采用）。
- **不做整段通知的 AI 抽取**，不做截图 OCR（那是另一条路线）。
- 不猜年份、不补 23:59、不把活动开始时间当截止时间、不做课程模糊匹配。
- 没有网络请求、没有云端、没有新依赖、没有数据库结构变更。

## 3. 解析器从哪来（**逐字节复制**，不重写）

Web 端的解析器 `frontend/src/ocr/noticeParser.js` 是**无依赖纯 JS**，带着一批历史回归用例。
本轮按授权书要求**原样复制**到原生侧，而不是重写一套正则：

```
frontend/src/ocr/noticeParser.js   ← 原件，本次一行未改
mobile/src/domain/noticeParser.js  ← 逐字节复制（SHA256 与原件一致）
mobile/src/domain/noticeParser.d.ts← 只为它补的一层类型声明
```

- 原生侧**不跨 Metro 根 import**，因此**不需要改任何 Metro / Babel / 打包配置**；
- 两边一致性由 `mobile/tests/noticeParserParity.test.mjs` 用 **SHA256 + 逐字节比较**守住：
  任何一次「顺手改一行」都会让这条测试失败，提示重新复制而不是在 mobile 侧改规则；
- 因此**前端解析器与原生解析器的保守语义完全相同**，不存在「两份逐渐漂移的正则」。

### 3.1 原生适配层（`mobile/src/domain/noticeTextAdapter.ts`）

复制的解析器在**原生特有的场景**下有两个真实缺口，本轮用一层**保守适配**补上，
仍然**不改解析器本体**：

1. **独立任务标题行的边界。** 用户一次粘一整段、既没有序号也没有空行时：
   ```
   数据结构作业：请于2026年10月18日22:00前提交实验报告。
   英语作业：请于2026年10月19日18:00前提交作文。
   ```
   解析器的兜底分段会把两行合成**一条**候选（两门课、两个时间）。适配层只在
   「**短标签（1–24 个汉字）+ 冒号 + 后面还有内容**，标签以任务名词结尾（作业/实验/报告/论文/作文/
   课程设计/考试/答辩/阅读…）、标签里没有日期时间、且不是提交要求/截止时间/邮箱这类**附加信息标签**」
   时才切分；切完还要求**每一组都真的有任务线索**，否则整块原样交给解析器。
   它**不碰序号行**（`1. …` / `① …` 交给解析器既有的分段规则）、不碰折行续写
   （上一行以「提交到 / 发送到 / 请 / 的…」结尾时继续留在同一组）、不碰邮箱与「提交要求：…」跟随行。
   一句话：**宁可少分，不可错分**。
2. **任务类型显式映射。** 解析器会给出 `LAB` / `REPORT` 这类**原生任务类型里没有**的值。
   `mapNoticeTaskType` 显式映射（`LAB`/`REPORT` → `PROJECT`，未知 → `OTHER`）并给出中文说明，
   **绝不 `as TaskType` 硬转**。映射说明会追加到任务说明里（放不下就不加，绝不截断正文），
   并在核对页以提示形式显示，保存后可以照着核对。

新增的纯映射层 `mobile/src/domain/noticeImport.ts` 只做：解析 → 可编辑草稿行 → 校验 →
（给仓库的）任务草稿。所有日期 / 课程判断都来自复制过来的解析器。

## 4. 保存到底写了什么

| 任务字段 | 来源 |
| --- | --- |
| `title` | 解析标题（可改，必填，≤200 字） |
| `description` | 这一组原文；**放不下（>1000 字）就留空**，不截断成半句；类型被映射过时追加一行映射说明 |
| `courseId` | 解析到的课程或你选的课程；保存时**再校验一次课程是否还在** |
| `type` | 解析类型（显式映射到原生类型，可改） |
| `status` / `priority` | 新建一律 `TODO` / `3`（与「新建任务」默认值一致） |
| `deadline` | 你确认后的北京墙上时间（空 = 未设置，**不会**补默认值） |
| `submitRequirement` / `submitMethod` | 解析结果（可改） |
| `task_sources.raw_text` | **整段粘贴的完整原文**（`ORIGINAL_TEXT`），含群名、消息头、前后空白与空行，**逐字**留存 |

**原文永远不会因为「说明放不下」而丢失**：说明只是顺手放一份，原文始终整份写进
`task_sources`，在任务详情页随时读回；关掉 App 再打开也还在（有重开数据库的回归测试）。
原文留档**不做 trim**：用户粘贴时带的前后空白与空行同样属于输入，逐字保存。

### 原子性与幂等

- 整批任务行 + 它们的原文在**同一个事务**（`BEGIN IMMEDIATE` / `COMMIT`）里写：
  任何一步失败整批 `ROLLBACK`，**不留孤儿任务、不留半批数据**；
- **不在循环里调用 `TaskRepository.create`**（那会每条任务开一个事务）；
  批量路径复用同一套 `normalizeTaskDraft` 校验与同一份列清单；
- **重复点保存 / 提交成功后重试 / 把同一份原文再导入一次**：只跳过
  「**原文 + 全部有意义字段都完全相同**」的行（标题、说明、课程、类型、优先级、截止时间、
  预计用时、提交要求、提交方式、原文）。
  **同标题但截止时间 / 课程 / 提交要求 / 原文不同的，照旧新建为不同任务**；
- **生命周期字段不参与去重**：用户把导入的任务标记成「已完成」之后再导入同一份原文，
  会**跳过**那条已有任务（保留它的完成状态），**不会**再建一条 TODO，也不会改写它；
- 去重键是 `JSON.stringify` 的**元组**（不是拼接字符串）：用户原文里出现 `|`、换行甚至
  NUL 也不会与他人撞键；「原文」这一项在写入与读回两侧使用**同一份口径**（都取 `trim` 后的那一条），
  不会出现「写入用带空白的、读回用 trim 的」导致永远判成不重复；
- 提交后**读回失败不谎报「没保存」**：返回 `committed: true` + 已提交的 id + `readbackError`，
  界面提示「已经保存，只是列表没刷新」，并且**不再提供重试保存**；
- 仓库层会拒绝**同一实例上的并发导入**（连点/并发调用时明确报错）；
  store 里则把通知导入放进**与任务 / 课程写入同一条公共串行队列**（`enqueue`，它本身不开事务），
  所以同一个 SQLite 连接上不会出现两条写入互相穿插。照片导入仍然保留它自己的队列
  （那一条自带外层事务，形态不同）。

### 校验与「已删除的课程」

- 校验全部在 `BEGIN` **之前**完成；不合法时抛 `ValidationError`，**什么都没写**；
- 保存前课程被删掉 → **可见地拒绝**（「第 N 行：选择的课程在本机已经找不到了」），
  不是静默改成「未关联课程」，也不是静默忽略；
- 行内的标题 / 时间等错误都带**行号**就地显示；
- 原文超过 10000 字 → 显式报错（含当前字数与上限），不截断、不写库；
- 勾选超过 30 条 → 显式报错，不悄悄砍掉后面的。

## 7. 已知限制（诚实声明）

- **相对时间不换算**（见第 2 节），需要用户手填或用任务表单里的时间助手；
- **不是 AI**：只覆盖第 2 节那几种写法，规则之外的文字可能提取不出候选（会如实显示「没有提取到」）；
- 课程匹配只做**完全一致**（名称或内部代码）。真同名同长的两门课会让该行保持「未关联课程」；
  能唯一确定更长课名时按最长匹配（这是复制来的解析器的既有语义，本轮没有改）；
- 标题行切分是**启发式**的：它只认「短汉字标签 + 冒号 + 标签里有任务名词」，因此
  **带数字编号的标签**（`英语作文一：`）不触发切分（交给解析器的序号规则），
  极不常见的写法可能仍然合并成一条候选 —— 界面允许用户自己拆分（把不要的行取消勾选，
  再单独导入另一部分）；
- 原文上限 10000 字 / 单次上限 30 条，都是**显式拒绝**而不是静默截断；
- 单次导入保存的每条任务都会带上**同一份完整原文**（这是「不丢原文」的代价：
  同一份公告导出的多条任务在任务详情里看到的是同一段全文，而不是各自那一小段）；
- 界面不提供「编辑已保存任务的原文」——原文写进去之后与现有任务一样只读留档；
- 截图像素级 OCR（通知截图）与本功能无关，仍未实现。

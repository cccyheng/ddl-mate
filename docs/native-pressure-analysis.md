# DDL 压力分析（native DDL pressure analysis）

**一句话**：未来 7 个上海自然日里，哪几天到期的「进行中」任务扎堆。

- 入口：**今天**标签页的「DDL 压力分析」小结卡片（按钮「打开 7 天压力分析」）；
  **任务**标签页筛选行里的「DDL 压力分析」按钮。两个入口打开的是**同一个原生界面**。
- 退出：界面右上角原生返回按钮 / 左滑返回手势（与其它原生页一致）。
- 路由：`TaskStack.Pressure` 与 `TodayStack.Pressure`（参数都是 `undefined`）。

这一页**只做集中度统计**，不做日程、不做通知、不做 AI、不碰课表冲突。

---

## 1. 这一页在用的时候到底算了什么

| 概念 | 实际口径 |
| --- | --- |
| 时间范围 | 从**上海今天**起 7 个自然日（含今天）。第 8 天起算「7 天之外」，只披露条数 |
| 统计对象 | 状态是「待办 / 进行中」的任务。**已完成 / 已取消完全不参与** |
| 归组依据 | 任务的 DDL 换算到 **Asia/Shanghai** 之后落在哪一天（与手机时区无关） |
| 每天的「已填预计用时合计」 | 那一天到期的任务里，**用户自己填的** `estimatedMinutes` 之和（分钟） |
| 每天的「N 条未填预计用时」 | 预计用时为空的条数；**负数 / 小数 / 无法解析的历史脏值也按未填处理** |
| 每天的「最早 DDL」 | 那一天最早的一个截止时刻（与有没有填预计用时无关） |
| 「扎堆」 | 那一天有 **≥ 3 个**进行中的截止任务（阈值在界面上显式写着） |
| 页头合计 | 7 天内所有进行中截止任务的条数 / 已填用时合计 / 未填条数 |

### 计数为什么不会重复

每个进行中任务**恰好**落进一个分类：

```
进行中任务
├── 有 DDL 且早于「现在」      → 「已逾期（进行中）」区块（含今天更早的时刻）
├── DDL 恰好等于「现在」        → 算今天到期，**不算逾期**
├── 今天（现在及以后）          → 今天的卡片
├── 第 2 … 第 7 天              → 对应那一天的卡片
├── 第 8 天及以后               → 「7 天之外」区块（不计入任何一天）
├── 没有 DDL                    → 「没有截止时间」区块
└── DDL 存在但解析不出来        → 「截止时间无法识别（需要修复）」区块
```

因此：**已逾期**的任务**不会**再出现在「今天」那张卡里；窗口内的条数之和 = 每天的条数之和。
比较是**按毫秒**做的，所以「19:59 到期」与「20:00 到期」在同一分钟内也分得清。

## 2. 每一天的结论怎么读

每天只给四种结论之一（文案与判定在 `mobile/src/domain/ddlPressure.ts` 与 `PressureScreen.tsx` 里）：

| 状态 | 什么时候 | 界面怎么说 |
| --- | --- | --- |
| `empty` | 这一天没有进行中的截止任务 | 「这一天没有进行中的截止任务。」 |
| `exceeds` | **已填**用时合计 > 参考用时 | 「已填预计用时超过参考 X（参考 Y）。」+ 若还有未填的，同时注明「实际可能更多」 |
| `unset` | 用户没有设置参考用时 | 「还没有设置每日参考用时，暂时只显示条数与合计。」（条数与合计照常显示） |
| `incomplete` | 有参考值、没超标，但**还有任务没填预计用时** | 「这一天的预计用时不完整……」——**不会**说「足够 / 安全」 |
| `within` | 有参考值、没超标、且预计用时都填了 | 「已填预计用时未超过参考（A / B）。」 |

**关键取舍**：

- **参考用时未设置（默认）时不比较**，也绝不替用户编一个参考值；
- **相等不算超标**（`已填 = 参考` → `within`）；
- `0 分钟`是**合法**的已填值（任务表单允许 0），它不进合计但**不算「未填」**；
- 合计的是**原始预计用时**，不是剩余工作量：进行中（DOING）的任务进度**没有被测量**，
  所以它按全额计入；
- 「未超过参考」**不等于**「时间一定够」——参考值只是一个比较基准。

## 3. 每日参考用时（可选设置）

- 存哪：既有的 `app_settings` 键值表，键 `pressure.daily_study_reference_minutes`。
  **没有新表、没有迁移、没有版本变更**（`SCHEMA_VERSION` 保持 3）。
- 取值范围：**1–1440 的十进制整数分钟**；**空 = 未设置**（默认）。
- 拒绝（界面与仓库用同一套判定 `parseStudyReferenceMinutes`）：小数 `30.5`、
  科学计数 `1e3`、带符号 `+30` / `-5`、单位后缀 `30m` / `30 分钟`、
  越界 `0` / `1441`、`NaN` / `Infinity`、逗号 `1,440`。
  非法输入**一个字节都不写**，输入框原样保留并显示原因。
- 界面上明确写出：这个参考值对 **7 天一视同仁**、**不会自动扣掉上课时间**、
  **没有考虑夜里还剩多少时间可用**。
- 清除 = **删掉这一项**（回到未设置），不是写入 0；需要用户明确确认。
- 保存参考用时**不修改任何任务或课程**（有真实 SQLite 测试断言任务 / 课程行完全不变，
  连 `updated_at` 都不动）。
- 库里读到脏值（早前手改、旧版本写坏、超出范围）→ 一律按**未设置**处理，不崩。

## 4. 界面行为

- **展开状态**：点某一天的卡片展开/收起那一天的完整任务列表。
  这个状态**只由用户点击改变**——刷新、保存参考用时、跨零点都不会把它重置。
- **每条任务**给出：任务名、所属课程、预计用时（未填时写明「统计里算作未知」）、
  DDL；点一下进任务详情，右边的「补预计用时」进任务编辑页。
  **应用永远不会替你填预计用时。**
- **逾期列表**默认只显示前 5 条，但一定有「显示全部 N 条」的出口（不会静默截断）。
- **零数据**时给出「新建任务」的真实动作，而不是一句空话。
- 加载失败 / 读快照失败沿用既有模式：`LoadingState` / `ErrorState`（可重试引导）/ `RefreshErrorBanner`。
- 时间用既有的聚焦时钟（`useFocusClock`）：页面可见时每 30 秒推进，回到前台立刻同步，
  跨零点自动切到新的一天并重读快照；**没有**自建的后台定时器。
- 读数取**真实毫秒**（`readShanghaiEpochClock`），逾期判定按完整时刻比较：今天页的小结与这一页
  用的是同一个口径，因此两处不会对「同一分钟内刚过的 DDL」给出不一样的答案
  （例如 20:00:00.250 时看 20:00:00.500 到期的任务，两边都不算逾期）。
- 离开时只对**真的有改动**的参考用时草稿弹一次原生确认（`usePreventRemove` +
  原始导航动作原样派发），没有改动不会被多问一次。

## 5. 明确**没有**做的事（这一轮的范围）

- 不生成每日计划、不自动重排任务、不发通知、不接任何 AI / 大模型；
- 不做课表冲突检测、不算「上课占掉多少时间」、不算「一晚上还能挤出几小时」；
- 不做 OCR、不读截图、不发任何网络请求；
- 不自动填写 / 估算任务的预计用时；
- 不改 `tasks` / `courses` / `schedules` 的任何数据（这一页唯一的写入是参考用时设置）。

界面里唯一的建议是一句静态小提示（「如果某几天扎堆，可以早点动手把任务分到更空的日子」），
它不是计划，也不会被保存。

# 任务步骤清单（原生）

「任务步骤清单」回答一个问题：**这条任务被我拆成了哪几步、哪几步做完了。**

它是一份挂在父任务下面的**手动清单**：不接 AI、不联网、不生成步骤、不发通知，
也不把步骤变成独立的日历任务。只有用户明确点「保存步骤」时才写入本机。

## 从哪里进

- 「任务」标签页 →「任务详情」→「步骤清单」；
- 「今天」标签页 →「任务详情」→「步骤清单」。

两条标签页各有自己的原生栈，所以从任意一条进去，返回手势与返回按钮都正常。
路由名是 `TaskSteps`，参数是 `{ id: number }`（父任务 ID），两条栈共用同一个界面。

## 使用流程

1. 打开时先读这条任务已经保存的步骤；读的过程中不允许编辑（避免拿「0 步」去覆盖未知版本）。
2. **添加一步**：最多 30 步，每一步写 1–120 个字（首尾空白会被去掉）。
3. **勾选 / 改内容 / 删除**：都只改当前草稿，**不写库**，页面上会显示「有未保存的改动」。
   - 删除有内容或已经勾选过的一步，会先确认；点「取消」时草稿原样保留。
4. **保存步骤**：把整份清单（= 你看到的全部内容）一次写入本机。
   - 把一条本来有已保存内容的清单删成空，会先确认「全部清空」。
   - 保存成功后基线对齐到刚保存的内容，页面变成「已保存」。
5. **离开**：有未保存改动时，任何离开动作都会先问一句；确认后继续原来的导航动作。

界面会显示父任务标题、父任务当前状态，以及「已完成 / 总数」。
**空清单显示「尚未添加步骤」，不会显示 0/0 或 100%。**

## 边界（刻意不做的事）

- 步骤**没有**自己的截止时间、预计用时、优先级或状态机；
- **全部步骤做完也不会把父任务标成完成**，不改父任务的 DDL、状态或预计用时；
- 父任务已完成（DONE）/ 已取消（CANCELLED）时，步骤清单仍然可以查看和编辑；
  父任务的状态只由用户在任务页自己改；
- 不支持拖拽 / 手动排序：步骤按你添加的顺序保存，编号稳定不变；
- 没有 AI 生成、通知提醒、每日计划联动。

## 保存了什么

存在既有的 `app_settings` 键值表里，**每条任务一个精确的键** `task_steps.<任务ID>`，
值是带版本号的紧凑 JSON：`{版本, 父任务ID, 版本号, 步骤:[{编号, 标题, 是否完成}]}`。
没有新表、没有 schema 版本变更、没有新依赖，也不存任何凭据。

- **一次事务**：保存时在同一个事务里确认父任务还在、读既有记录、比对版本号、写入；
  任何一步失败都一个字节都不写。
- **乐观锁**：保存按「草稿当初基于的那一版」提交。别处先保存过就拒绝，并回传当前版本，
  界面会暂停保存、给出「载入最新版本（丢弃草稿）」的明确选择，**绝不静默覆盖**。
- **严格解码**：坏 JSON、不认识的版本、非法编号 / 标题 / 重复编号 / 超过 30 步 ——
  整条记录判定「读不出来」，界面如实说明并**原样保留**那条记录，也不会拿草稿去覆盖。
- **公开读取也确认父任务**：任务已被删除时，读取返回「任务不在」，不会把一条孤儿记录
  当成这条任务的清单展示。
- **删除任务时**：只删 `task_steps.<这条任务ID>` 这一个键，并与任务行、来源文本在
  **同一个事务**里完成；不会用前缀 / LIKE 批量删除，别的任务的清单与无关设置不受影响。
  清理失败会整体回滚，任务不会被删成一半。
- **读取绝不写库**：正常读取只有查询，不会创建表或写入任何东西。

## 刷新、冲突与读回失败

- **重新聚焦会重读**，但只在**草稿没有未保存改动**时才用库里的内容对齐草稿；
  脏草稿（包括被有意清空成 0 步的草稿）一个字都不会被刷新覆盖。
- 后台读到了**更新的版本**时：草稿与「草稿基版本」都保留，页面标出「别处有更新」，
  保存暂停；只有用户确认「载入最新版本（丢弃草稿）」才会整份替换。
  确认之后、读回完成之前，编辑与保存会**同步冻结**，避免刚输入的内容被随后到达的
  旧读回覆盖；取消确认不会碰草稿。
- **保存已提交、但随后读回失败**：页面明确写「已保存但暂时无法读取」，保留版本号，
  只提供「重新读一次」，不会把旧内容当新的，也不会让你再保存同一份草稿。
- **缺失 / 空的步骤输入**不会被当成「清空」：传入的步骤必须真的是一个数组，
  显式的空数组才是合法的清空；畸形输入直接拒绝，已保存的清单原样保留。

## 验证

- 新增测试 56 条：纯逻辑 6、状态机 22、真实 SQLite 持久化 15、接线 13。
- 受影响既有测试 147 条（任务仓库、课表批量、通知导入仓库、时间助手保存、照片运行时、
  今日计划 / 压力分析接线）全部通过。
- `tsc --noEmit` 通过。
- 真实 SQLite 覆盖：保存 / 读取 / 重开数据库、过期版本冲突、父任务缺失或删除时零写入、
  坏记录原样保留、写入失败全有或全无、提交后读回失败如实报告、
  删任务精确清键且保留别的任务、清理失败整体回滚、全部步骤做完父任务字段不变。

**限制**：上述 SQLite 是 Node 侧 `node:sqlite`，验证 SQL 与仓库 / 状态逻辑，
验证不了 iPhone 上的 `expo-sqlite` 原生绑定、真机手势与视觉布局；
本轮没有在模拟器 / 真机上跑界面。测试只使用系统临时目录与内存库，不碰真实用户数据。

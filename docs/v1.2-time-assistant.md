本文档说明**实际支持**的短语、**必须保守拒绝**的写法，以及前端「显式采用才写入」的交互契约。
时间助手是**本地确定性规则**，不调用大模型、不访问外部服务、不加任何依赖。

## 1. 能力范围（一句话）

在「新建 / 编辑任务」的截止时间旁、以及通知导入的每条候选旁，提供一个**可折叠的时间助手**：

1. 用户输入**简短时间短语** + 一个**带偏移量的参考时间**（默认现在的北京时间，可改成通知发布时间）；
2. 可选结合**用户在表单 / 候选里明确选择的课程**与**真实课表**，把「下节课前」这类说法算成具体时间；
3. 助手展示「解析出的北京时间 + 理由（+ 课表匹配信息）」；
4. **只有用户点「采用此时间」，才会写入表单或候选**；不采用就什么都不改，采用后仍可手工修改。

解析接口是**只读**的：`POST /api/tasks/resolve-time` 不会创建 / 修改任何任务、课程、课表或来源。

## 2. 接口契约

### 请求

```http
POST /api/tasks/resolve-time
Content-Type: application/json

{
  "text": "下周五上课前",
  "referenceAt": "2026-10-10T12:00:00+08:00",
  "courseId": 3
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `text` | 是 | 简短时间短语，1–500 字；**不是**整段通知 |
| `referenceAt` | 是 | **必须带偏移量**的明确时间（`2026-10-10T12:00:00+08:00` 或 `…Z`）。缺偏移量直接 400，避免把「今天」算到错误的自然日 |
| `courseId` | 否 | 「课前」类说法需要；不存在返回 404 |

### 响应

```json
{
  "status": "RESOLVED",
  "message": "已按课表匹配到「数据结构」的下一节：2026-10-16 周五 08:00。",
  "hints": [],
  "referenceAt": "2026-10-10T12:00:00+08:00",
  "referenceLocal": "2026-10-10 12:00 周六",
  "timeZone": "Asia/Shanghai",
  "candidates": [
    {
      "deadline": "2026-10-16T08:00:00+08:00",
      "reason": "“下周五上课前” → 数据结构 2026-10-16（周五）08:00 上课前（北京时间 +08:00）",
      "kind": "COURSE_BOUNDARY",
      "past": false,
      "courseBoundary": true,
      "courseId": 3,
      "courseName": "数据结构",
      "scheduleId": 7,
      "scheduleDate": "2026-10-16",
      "scheduleStartTime": "08:00",
      "scheduleWeekday": "周五",
      "scheduleLocation": "教三 305",
      "note": "课前完成：按开课时间作为截止边界，助手不会提前扣分钟。"
    }
  ]
}
```

四种状态（互斥）：

| status | 含义 | candidates |
| --- | --- | --- |
| `RESOLVED` | 解析成功，给出明确 `+08:00` 截止时间与理由（课表匹配还带 `scheduleId / scheduleDate / scheduleStartTime`） | 1 条 |
| `NEEDS_INFO` | 说法能认出来，但信息不足（只有日期 / 只有时刻 / 今晚 / 尽快 / 周末 / 范围 / 多重时间 / 缺课程） | 空 |
| `UNSUPPORTED` | 否定、延期、更改、「…以前」、需要校历等复杂说法，保守拒绝 | 空 |
| `NO_COURSE_MATCH` | 课程说法成立，但**约定窗口内**课表没有匹配（绝不越周硬找） | 空 |

错误：`text` 为空 / 超 500 字 → `400 VALIDATION_FAILED`；`referenceAt` 缺偏移量、格式非法、年份超出 1900–2199 → `400 INVALID_ARGUMENT`；`courseId` 不存在 → `404 RESOURCE_NOT_FOUND`。**极端输入不会变成 500。**

## 3. 明确支持的短语

日历语义**固定**：业务时区 `Asia/Shanghai`，一周从**周一**开始；「本周」= 参考时间所在的自然周（周一 00:00 起），「下周」= 严格下一个自然周。

### 3.1 相对日 + 明确时刻

| 写法 | 结果 |
| --- | --- |
| `今天 22:00` / `明天 18:00` / `后天 08:30` | 对应日期的该时刻 |
| `大后天 07:00` | 参考日 +3 天 |
| `今晚 8点` / `明晚 8点` | 今天 / 明天 20:00 |
| `明天下午3点` / `明天晚上8点半` | 15:00 / 20:30 |
| `明天中午1点` | 13:00（口语习惯） |
| `明天凌晨1点` / `明天上午9点` | 01:00 / 09:00 |

时刻写法：`22:00`、`22点`、`22点30`、`22点30分`、`8点半`、`3点一刻`。
半日前缀：凌晨 / 早上 / 早晨 / 上午 / 中午 / 下午 / 傍晚 / 晚上 / 今晚 / 明晚。

### 3.2 星期与周前缀

| 写法 | 结果 |
| --- | --- |
| `本周五 18:00` / `这周六 09:00` | 本周对应的那一天（**即使已经过去也如实解析**，结果会带「已过去」提示，绝不偷偷滚到下周） |
| `下周一 08:00` / `下星期五 20:00` / `下个星期三 10:00` | 下一个自然周对应的一天 |
| `下星期X` / `本星期X` / `这个星期X` / `这星期X` | 同上 |
| 不带周前缀的 `周五 18:00` | 按**本周**理解；**这一天本周已经过去时不自动跳周**，返回「需要补信息」并要求写「下周五」或具体日期 |

### 3.3 精确日期

`2026-10-20 23:00`、`2026-10-20T23:00`、`2026年12月31日 23:30`、`2027-01-01 00:00`（跨月 / 跨年 / 闰日 2028-02-29 都可）。

### 3.4 课程边界（必须由用户明确选择课程）

精确支持的短语**只有**：

```
下节课前 / 下节课之前 / 下一节课前
下次课前 / 下次课之前 / 下次上课前 / 下次上课之前
本周这门课前 / 这周这门课前 / 下周这门课前 / 下个星期这门课前
本周X上课前 / 这周X上课前 / 下周X上课前
```

规则：

- **课程必须由用户明确选择**（表单里的「所属课程」或候选里的「课程」）。助手不会从文字里替你挑课；
  文字里出现**另一门已有课程**的名称 / 代码时，返回「需要补信息」，不会忽略它按当前课程算；
- 复用全站唯一的教学周判定 `ScheduleRules.occursOn`：遵守**学期第一周周一、起止教学周、ODD/EVEN 单双周**，
  旧课表（没有教学周信息）按**每周**处理；
- **参考时间之后才开始的课**才算「下一次」：正在上的那节课不算；
- 窗口语义：
  - `下节课前 / 下次课前` → 参考时间起**最多向后 366 天**找最近一节；
  - `下周…` → **严格下一个自然周**（周一~周日）；这一周没有课就返回 `NO_COURSE_MATCH`，**不会越周**去更远找；
  - `本周…` → 参考时间当天起、到本周日为止剩下的日子；
  - `本周五上课前 / 下周五上课前` → 只考虑那一天；
- 一个窗口内有多节时，**取最早的一节**并在 `note` 里说明「该窗口内还有 N 节更晚的课」；同一时刻的重复课表会**去重**；
- **候选截止 = 上课开始边界**，`note` 明确写「按开课时间作为截止边界，助手不会提前扣分钟」；
- 该课程没有课表、或窗口内没有课 → `NO_COURSE_MATCH` 并解释窗口范围。

## 4. 必须保守拒绝 / 要求补全的写法

时间助手宁可要求用户补全，也不猜。

| 输入 | 结果 | 说明 |
| --- | --- | --- |
| `明天`、`下周五`、`本周一` | `NEEDS_INFO` | **只有日期没有时刻**：绝不默认 23:59，也不默认 00:00 |
| `22:00`、`今晚`、`下午3点` | `NEEDS_INFO` | 只有时刻 / 只有半日信息 |
| `尽快`、`随时`、`有空`、`以后` | `NEEDS_INFO` | 不是确定时刻 |
| `周末`、`月底`、`月初`、`下周` | `NEEDS_INFO` | 范围太宽，要具体到某天 + 时刻 |
| `每周五 18:00` | `NEEDS_INFO` | 重复时间，不是一次性截止 |
| `明天 10:00，后天 12:00` | `NEEDS_INFO` | 多个日期，**不取第一个静默成功** |
| `明天 10:00 或 14:00` | `NEEDS_INFO` | 多个时刻 |
| `本周一到周五`、`2026-10-01 到 2026-10-07` | `NEEDS_INFO` | 范围 |
| `10月20日 22:00` | `NEEDS_INFO` | 只有月日没有年份 |
| `明天 25:00`、`明天 22:75`、`2026-02-30 10:00`、`2027-02-29 10:00` | `NEEDS_INFO` | 时刻 / 日期不存在，严格校验 |
| `明天下午15点`、`明天上午23点`、`明天凌晨12点`、`晚上12点` | `NEEDS_INFO` | 半日与时刻矛盾 / 中午还是午夜不明确 |
| `下下周五18:00` | `NEEDS_INFO` | 不做「下下」这种未支持的周偏移，**不截成「下」** |
| `明天18:000`、`明天123:00` | `NEEDS_INFO` | 多余数字**不会被截断后静默采用** |
| `明天18:00之后`、`明天18点开始` | `NEEDS_INFO` | 未定义的修饰词（`之后` / `开始`） |
| `下节课前两小时` | `NEEDS_INFO` | 不做"提前两小时"这类换算，避免替你改截止边界 |
| `下节课前或下周五上课前` | `NEEDS_INFO` | 多个「课前」条件，不取第一个 |
| `下次数学课前`、`下次实验课前`、`下周实验课前` | `NEEDS_INFO` | 带课程名 / 类型限定的「课前」不猜是哪一节；请明确选择课程或写明确时间 |
| `上课前`、`课前` | `NEEDS_INFO` | 缺少「下节 / 下次 / 本周 / 下周」作用域 |
| `取消明天的作业`、`延期到下周五`、`改到下周 22:00` | `UNSUPPORTED` | 否定 / 延期 / 更改 |
| `三天以前`、`两周之前` | `UNSUPPORTED` | 相对过去的说法 |
| `国庆后第一节课前`、`寒假前`、`考试周` | `UNSUPPORTED` | 需要校历（`semesters` 扩展），当前没有校历数据 |

### 允许的「包装词」（不改变语义）

在日期 / 时刻之外只允许有限的白名单，其余字符一律拒绝（**整句覆盖**策略，不依赖否定词黑名单）：

- 空白与标点；
- `前` / `之前` / `截止` / `截至`；
- `提交` / `提交到` / `上交` / `上传` / `发送` / `完成`；
- `请` / `请在` / `请于` / `于` / `在` / `的` / `要` / `需` / `需要` / `务必`。

例如 `明天18:00前交`、`明天 22:00 截止`、`明天18:00之前` 可以通过；`明天18:00左右`、`明天18:00之后` 会被拒绝。

## 5. 时区契约（固定北京时间）

- 时间助手**固定** `Asia/Shanghai`（`ZoneId.of("Asia/Shanghai")`），**不跟随** `DDLMATE_TIME_ZONE` 环境变量；
- 响应里的 `timeZone` 恒为 `Asia/Shanghai`，所有 `deadline` 一定是带 `+08:00` 的 ISO 字符串；
- 参考时间允许带别的偏移量（例如 `2026-10-09T16:30:00Z`），后端会**先换算到上海自然日**再算「今天 / 明天」；
- 前端「新建 / 编辑任务」表单的 DDL 统一按**北京墙上时间**填写与提交（`shanghaiWallClockToOffset` 显式补 `+08:00`），
  在 **UTC 浏览器**里也不会少 8 小时；
- 时间助手自己的「参考时间」输入框同样是上海墙上时间，并显式标注「北京时间 +08:00」。

  显式采用后调用现有的 `markEdited(candidate, 'deadline')`，候选的生成身份 / 来源 / 冲突 / stale / 防重写 / 保存冻结规则完全不变；
- **过期建议保护**（`frontend/src/utils/timeAssistantGuards.js`）：
  - 短语 / 参考时间 / 课程 / 当前 DDL 任一变化 → 立刻作废已展示的建议并禁止「采用」；
  - 迟到的响应若上下文已变、序号已换、或组件已卸载 / 关闭 → **不写回任何状态**；
  - 保存期间（`disabled`）助手按钮全部禁用，不能采用；
  - 表单 / 候选里的 DDL 在解析期间被手工改动 → 旧建议作废，不会被它覆盖；
- 手工输入始终保留：助手只改截止时间一个字段，采用后仍可继续手改。

## 9. 已知限制（不夸大）

- **不是大模型**：不做整段通知的语义抽取，复杂句（否定 / 延期 / 更改 / 范围 / 相对过去）一律保守拒绝；
- 需要校历的说法（国庆、寒假、考试周、「第几教学周」）不支持，规划为 `semesters` 扩展；
- 「下下周五」这类多周偏移不支持（保守拒绝），「周X」不带周前缀时按本周理解且已过去不跳周；
- 课表匹配只按**课程 + 星期 + 教学周规则**，不区分同一门课的「理论 / 实验」课堂类型，因此带类型限定的
  「下次实验课前」被拒绝而不是猜一节；
- 时间助手是**辅助输入**，最终是否采用、是否修改由用户决定；解析结果不写库。
- 实现阶段本机沙箱里的 `vite build` 因 esbuild 子进程 `spawn EPERM` 未能执行（与历史轮次相同的沙箱限制）；
  该问题已由 Codex 提权正常构建解决，最终构建与真实浏览器验收均在授权环境完成（`.supervision/v12-build.log`、`v12-browser-review.json`）。
